NAND 一个格子存 3 个 bit：TLC 的 8 个峰是怎么来的

发表于2026-11-13|更新于2026-11-21|从 Cell 到 SSD
|总字数:3050|阅读时长:10分钟|浏览量:
声明这是一份学习笔记，不是厂商文档。文中所涉规范与参数，参考 ONFI、JEDEC 等公开标准，以及闪存阈值分布与编码方案方面的公开研究整理；观点仅代表个人，与任职单位无关，也不涉及任何厂商未公开的参数或商业秘密。为讲清机制，部分案例与数字做了简化或假设，插图中的时序与比例均为示意画法，不能当作选型依据，也不是商业建议。发现错漏欢迎指出。

前言：上一句留下的坑

上一篇算完那笔账，结尾留了一句：几百万个 Cell 的 Vth，不可能整齐划一。

确实不可能。它们会散成一堆钟形的峰。而问题在于——TLC 要在同一个电压窗口里，塞进 8 个这样的峰。

8 个峰，每个峰还要有自己的名字、自己的位置、自己的读取电平。这件事听起来只是“多分几档”，但它牵出来的东西比想象中多：为什么峰一定是钟形？峰和峰之间挤到什么程度就不能再挤？为什么 8 个峰的排列顺序，会影响一颗芯片的可靠性上限？

这一篇就拆这三件事。

一、一个 Cell 里怎么塞进 3 个 bit

先把“分档”这件事说清楚。

SLC 一个 Cell 存 1 个 bit，只有两种状态：擦除态和编程态。反映到 Vth 上，就是两个峰，中间设一个判断电压，高于它是 0，低于它是 1。

想存更多，办法很朴素：把 Vth 窗口切得更细，让每个 Cell 停在更精确的位置上。

类型 bit/Cell Vth 峰数 Read Level 数 每档可用宽度（相对 SLC）
SLC 1 2 1 1
MLC 2 4 3 约 1/3
TLC 3 8 7 约 1/7
QLC 4 16 15 约 1/15

规律很简单：N 个 Read Level 分出 N+1 个区间。峰数每翻一倍，相邻峰的间距就砍一半，留给每个峰“站住”的地方越来越窄。

这里有个容易被忽略的事实：电压窗口本身并没有变大。不管你存几 bit，Cell 能用的 Vth 范围还是那么大——受限于氧化层耐压、读取电路的动态范围、以及不能把 Vth 顶到太高（否则读的时候会干扰到旁边的字线）。窗口不变、档位翻倍，只能靠压缩每一档的空间来换容量。

这就是“容量翻倍”背后的真实代价：不是凭空多存了东西，而是把同一段尺子画得更细，然后要求每一粒电子都站得更准。

二、为什么一定是钟形，不是一条线

理想情况下，同一个状态的几百万个 Cell，Vth 应该完全一样，画出来是一根竖线。

现实里它是一条钟形曲线。原因不是某个“误差”，而是一堆互相独立的随机因素在叠加。

两个绕不开的随机性

第一是杂质的随机分布。 沟道和电荷存储层里会残留随机分布的杂质、晶格缺陷。它们形成局部的电势陷阱，让电子移动时的阻力各不相同。这颗 Cell 的杂质恰好少一点，电子就进得容易，Vth 偏低；那颗多一点，就偏高。

第二是结构本身不完美。 氧化层厚度在原子尺度上是有波动的，界面也是粗糙的。隧穿概率对厚度极其敏感（上一篇讲过，近似指数关系），所以氧化层薄一点点的地方，电子进出都更容易——Vth 偏低；厚一点点的地方，进出都难——Vth 偏高。

一颗 Cell 的 Vth，是这两类因素加上几十个别的微小扰动共同作用的结果。它们彼此独立、方向随机。

中心极限定理在这个场合几乎是教科书式的应用：大量独立随机变量求和，其分布趋近正态分布。所以只要随机因素足够多、足够独立，峰就一定是钟形的。

这件事有个重要的引申：峰宽是物理决定的下限，不是设计者可以随便收窄的参数。 你能通过工艺改进（更纯净的材料、更均匀的氧化层）把峰压窄一点，但压不到零。技术节点越往后，Cell 越小，杂质和厚度的相对波动反而越大——峰会更宽。

ISPP 让峰变窄，但也只能到一定程度

上一篇讲过 ISPP：一个脉冲一个脉冲往上垫，每垫一次校验一次。这个机制本身就是在对付“峰太宽”——小步走，冲过头的概率就低。

但 ISPP 自己也会引入新的抖动：

  • 校验（Verify）本身有噪声：判断“到没到”这件事不是绝对可靠的；
  • 最后一个脉冲的落点：运气好刚好到，运气差稍微过一点，这仍是一个随机量；
  • 电子数太少：上一篇算过，一个状态只对应几百个电子。几百个电子的统计涨落，本身就足够明显——少三五个电子，Vth 就动了。

所以峰宽是两头夹出来的：物理随机性给出下限，ISPP 的精度决定实际能做多窄。哪怕用最好的工艺和最细的步进，峰也不可能是一条线。

三、8 个峰挤在一起会发生什么

现在把 8 个峰放到同一段窗口里。假设窗口是几伏的量级（实际值随代际变化，这里只说量级），7 个间距分掉它，每个峰能占的宽度就只有零点几伏。

而相邻峰之间的判断电压，就落在这个零点几伏的缝隙里。

于是“读错”变成一件很具体的事：某个 Cell 的 Vth 因为涨落、因为老化、因为温度漂移，越过了它不该越过的判断线，读出来就变成了隔壁的状态。这个错误在物理层面无法彻底消除，只能靠两件事兜底：

  1. 留出间距——不要为了多存一点把峰挤到贴住；
  2. 加纠错码（ECC）——读出错了，后级把它修回来。

这也解释了一个常被问的问题：为什么 TLC 比 SLC 慢、比 SLC 短命？ 表面上是“多读了几个电平”，深层原因是每一档的可容错空间被压缩了：擦写一次造成的氧化层损伤，在 SLC 里可以被宽峰容下，在 TLC 里就成了压垮相邻峰的那一点点偏移。

容量、速度、寿命，仍是同一笔账。

四、格雷码：相邻峰只差 1 个 bit

接下来是这篇文章最有意思的部分。

TLC 的 8 个状态，是 3 个 bit 的 8 种组合。最自然的排法是按二进制数顺序：

但主流 NAND 不这么排。它们用格雷码（Gray Code）：任意两个相邻状态，只有 1 个 bit 不同。

以上图这个 2-3-2 方案为例，8 个峰从低到高排开，可以观察到：相邻峰之间的差异永远只落在一个 bit 上——有的位置上变的是 CSB，有的位置变的是 MSB。

为什么这件事值得单独设计

因为读错的时候，错多少很重要。

假设某一个 Cell 的 Vth 漂了一点，越过了判断线，被读成了隔壁峰的状态：

  • 用普通二进制：某些相邻状态之间会同时翻转 3 个 bit。比如 011 → 100，三位全变。这一下就错了 3 个 bit，ECC 需要纠正的错误数直接翻三倍。
  • 用格雷码：任何一次越界，最多只错 1 个 bit。

一个 Cell 只错了 1 个 bit，对一个能纠几十 bit 的 LDPC 码来说，是很轻的负担；而一次错 3 个 bit，在同一个 codeword 里密集出现，纠错压力就完全不同了。

换句话说，格雷码不是在优化“会不会错”，而是在优化“错了以后有多难修”。

三个 bit 的权位不一样

8 个峰对应 3 个 bit，这三个 bit 在物理上有名字，也有优先级：

缩写 别名 含义
LSB LP（Lower Page） 最低有效位
CSB UP（Upper Page） 中间位
MSB XP（Extra Page） 最高位

注意别名那列：这三个 bit 在芯片里对应三个不同的 Page。也就是说，往一个 Cell 里写 3 个 bit，不是一次写完的，而是分三次、写进三个逻辑页。这一点在下一篇讲读取时会用到——读一次 Page，其实是在读同一个物理位置的不同 bit 层。

至于为什么 LSB / CSB / MSB 的读取次数不一样（2 次、3 次、2 次），下一节就看到了。

五、读一个 bit，要读好几次

这里有个反直觉的地方：既然有 7 个判断电压，为什么不一次性把所有电平都扫一遍，直接定位到哪个峰？

因为没必要，而且慢。

实际上，芯片只在你要求读某个 Page 的时候，才施加与该 Page 相关的那几个 Read Level，然后把几次判断的结果做逻辑运算。

以 2-3-2 方案为例，三个 bit 的读取分工是这样的：

bit 别名 读取次数 涉及的电平
LSB LP 2 RL1、RL5
CSB UP 3 RL2、RL4、RL6
MSB XP 2 RL3、RL7

读 LSB 只要 2 次判断，读 CSB 要 3 次。这个数字不是随便定的，它由格雷码的排列方式决定——每个 bit 在 8 个峰之间翻转的次数不同，需要的判断次数就不同。

这也带来了一个很实际的性能差异：同一个物理位置，读 LP、UP、XP 三页的耗时并不相同（CSB 要多读一次）。在固件层做读缓存、预读策略时，这个差异是绕不开的。

（顺带说一句，不同厂商用的格雷码方案并不一样，常见的有 2-3-2、1-2-4、1-3-3 几种。方案的选择会牵动读写速度、错误率、ECC 复杂度和功耗，是一个典型的多目标折中。这里不展开，也不臆测各家具体用了哪一种。）

总结：8 个峰的四层理解

  • 峰的个数 = 2 的 bit 数次方，峰越多，每档越窄，但电压窗口不会跟着变大——容量是用精度换的。
  • 峰一定是钟形，因为它由一堆独立随机因素叠加而成（中心极限定理）；峰宽有物理下限，压不到零。
  • 相邻峰只差 1 个 bit 是刻意设计的（格雷码），目的不是减少出错，而是让出错时最多只错 1 个 bit，好让 ECC 修得动。
  • 读一个 bit 不等于加一次电压，而是施加与该 bit 层相关的几个电平、再做逻辑组合——所以读 LP 和读 UP 的耗时都不一样。

3 个 bit 已经挤成这样了。那往同一个格子里再塞第 4 个 bit 呢？

这就是 QLC。多出来的这一个 bit，把 8 个峰变成 16 个——相邻峰之间只剩一半的距离，而每个 Cell 里能用的电子数，一个也没多。

更麻烦的是：这一次连“一遍写到位”都做不到了。主流 QLC 基本都要写两遍，而且两遍怎么分工，是一笔明码标价的账：要么写得快、读得慢，要么读得快、写得慢。
