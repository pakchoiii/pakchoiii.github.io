NAND 800MT/s 之后：DQ Training 的四道体检

发表于2026-11-17|更新于2026-11-19|从 Cell 到 SSD
|总字数:3109|阅读时长:10分钟|浏览量:
声明这是一份学习笔记，不是厂商文档。文中所涉规范与参数，参考 ONFI、JEDEC 等公开标准，以及各厂商公开的接口应用笔记整理；观点仅代表个人，与任职单位无关，也不涉及任何厂商未公开的参数或商业秘密。为讲清机制，部分案例与数字做了简化或假设，插图中的时序与比例均为示意画法，不能当作选型依据，也不是商业建议。发现错漏欢迎指出。

前言：从介质到接口

前面几篇讲的全是 Cell 内部的事：电子怎么进去、Vth 怎么分布、电平怎么判断、错怎么修。

但这些事干完之后，数据还躺在一颗芯片里。要把它送到主控手里，得走一段几十根 DQ 线并行的路。频率低的时候，这段路随便走都没事；频率一高，麻烦全来了。

NAND 的规范里有一句很直接的话：速率超过 800 MT/s 的系统，应当支持 Training。 800 MT/s 是什么概念？每秒 8 亿次传输，一个单位间隔（UI）只有 1.25 纳秒——光在真空里跑 1.25 纳秒，也就 37 厘米。

在这个尺度上，走线长短差一点、负载电容差一点、温度变一点，信号到达的时刻就不一样了。而采样必须在数据稳定的窗口正中间，不能停在跳变的边沿上。

Training 就是干这件事的：把 NAND 和主控两端的时序、阻抗、参考电压对齐。业内常把它分成四道体检，一道治一种病。

一、第一道：ZQ —— 阻抗对不上，信号就会反射

先看最底层的问题：阻抗。

高速信号走到传输线末端，如果末端阻抗和线阻抗不匹配，一部分能量会反射回来。反射波叠在原始信号上，波形就出现了过冲、下冲、台阶——眼图一下子收窄。

NAND 的 I/O 电路里有一组可以开关的电阻网络，用来调整输出阻抗。问题是：这颗电阻会随工艺、电压、温度漂移。 常温下匹配得好，跑热了就不匹配了。

所以需要一把“标尺”。芯片上有一根叫 ZQ 的引脚，外面接一颗高精度参考电阻（精度通常在 1% 量级）。校准的时候，芯片把自己的内部电阻网络和这颗外部电阻做比较，一路调到匹配。

长校准与短校准

ZQ 校准分两种，用途完全不同：

长校准（tZQCL） 短校准（tZQCS）
目的 建立初始基准 跟踪微小漂移
时机 上电初始化、退出自刷新、温度剧变 正常运行中周期触发
耗时 较长，时钟周期的数百倍量级 短一个数量级
功耗 较高 很低
期间总线 不能有任何操作 不能有任何操作

三个细节值得注意：

  1. 校准期间不能动总线，连读状态都不行。校准是在改自己身上的电阻，这时候去问它“你好了吗”，只会得到错误答案。
  2. 校准时 DQ 要置高阻（High-Z）。理由同上：这时候 DQ 上的电平不代表任何东西。
  3. 主控端要同步校准。阻抗匹配是两端的事，只有 NAND 那头调好了没用。

什么时候必须做

规范里的要求分档：

  • NV-DDR3 接口、速率超过 400 MT/s：ZQ 校准是可选的，但推荐做；
  • NV-LPDDR4 接口：无论速率多少，都必须做。

这个差异不是随便定的。LPDDR4 的速率起点更高、摆幅更小，对阻抗匹配更敏感，干脆把它变成强制项。

还有个实践中的顺序问题：驱动强度（Drive Strength）和 ZQ 校准谁先谁后？ 规范里没有强制要求，但高速流程里通常是先设驱动强度，再做 ZQ 校准。因为 ZQ 校准的目标值本身就依赖驱动强度设定——先定音量，再校准音准。

二、第二道：DCC —— 时钟的两个半边不等宽

第二道体检针对的是时钟。

NAND 的接口时钟是差分的一对：RE_t 和 RE_c。理想情况下，一个周期里高电平和低电平各占一半，占空比 50%。

实际做出来不是。工艺偏差、驱动能力不对称，会让其中一个半边略宽、另一个略窄。占空比一旦偏了，有效的数据窗口就缩水了——因为采样窗口是由时钟沿定义的，一个沿早了，窗口就被吃掉一块。

DCC（Duty Cycle Correction，占空比校正）就是修这个的。规范给了两条路：

路子一：用 Set Feature 开使能，再发 Random Out。

  • 先把 Set Feature 20h P1[0] 置 1，打开 DCC 使能位（DCCE_EN）；
  • 然后发一个 Random Out 时序。返回的数据不用管——这次操作的目的不是取数据，而是让 NAND 在 RE 翻转的过程中自我校准；
  • 校完查 SR[0]。失败的话，主控调整 REDCC 相关配置，重来一次；
  • 成功后记得把 DCCE_EN 关掉。

路子二：用命令触发。

  • 发 18h 读命令，读回的长度是完整的 Page Size；
  • 同样不处理返回数据；
  • 查 SR[0]。失败要先发 FFh 复位，主控再调 REDCC 重新校准。

两条路的区别在于触发方式和失败后的恢复流程，本质上都是“让时钟跑起来，自己量自己的占空比”。注意那个“不处理返回数据”——第一次看到这里容易困惑：既然读了为什么不看？因为这一读只是给芯片一个“跑起来”的机会，数据本身没有意义。

三、第三、四道：DQ 与 DQS 的相位

接下来是最核心的两道，也是“Training”这个词最常指的东西。

先认两个信号：

  • DQ：数据线，通常 8 位一组；
  • DQS：数据选通（Strobe），差分的一对，作用是告诉接收方“现在该采了”。

理想情况下，DQS 的边沿应该正好落在 DQ 数据窗口的正中间。这样采样点离前后两个跳变都最远，容错空间最大。

实际上不是。因为 DQ 和 DQS 是两组不同的线，走线长度、负载、驱动能力都不同，到达时刻一定存在偏差（Skew）。 偏差大到一定程度，采样点就落到数据跳变的边沿上——采到的是“正在变”的值，读出来是乱的。

Read DQ Training：调接收端

读方向的数据是 NAND 发出的，主控改不了 NAND 的发送时序，能改的只有自己接收端的延迟。

流程是这样的：

  1. NAND 输出一段固定内容的测试数据（16 Byte，部分厂商支持 32 Byte），内容由地址决定，有 Inverse Set / 1st Pattern / 2nd Pattern 几种；
  2. 主控调节接收端 RDQ 与 RDQS 的相位/延迟，反复读这段数据；
  3. 找到能正确读出的延迟范围，把采样点定在这个范围的中心。

那 16 Byte 还是 32 Byte，可以通过 Set Feature FA 20h P3 配置（部分介质固定不可配）。

Write DQ Training：写进去再读回来

写方向的偏差方向相反：主控发出 DQ 和 DQS，NAND 接收。所以这次要调的是主控的发送端。

但写训练没法直接“看”结果——数据是发出去的，得验证它真的写对了。所以流程是：

  • 63h：主控把测试数据发给 NAND；
  • 64h：主控再把它读回来；
  • 比对读回的内容和预期是否一致。

一致就是这次延迟可用，不一致就换个延迟再试。写入的数据长度由 NAND 预先定义，可以通过 Get Feature 20h P3[3:0] 查。

Write Training 比 Read Training 慢，原因就在这个“写—读—比”的循环：每试一个延迟点，都是一次完整的写加一次完整的读。

怎么定那个“最佳点”

不管是读还是写，最后都要回答一个问题：延迟调到多少最合适？

通用的做法很朴素：扫一遍，找到能正常工作的左右两个边界，取中间。

为什么不取边界？因为边界只是“现在能用”。温度变了、电压漂了、芯片老了，边界会移动。取中点意味着两边都留了余量，一侧恶化时还有空间。

这个思路在工程上有个名字：时序余量（Timing Margin）最大化。它不是 NAND 独有的，DDR 内存的训练、高速 SerDes 的均衡，用的都是同一套逻辑。

Internal VrefQ：电压维度上的校准（LPDDR4）

还有一道附加题，只在 NV-LPDDR4 模式下有：内部参考电压 VrefQ 的校准。

前面三道调的都是“时间”，这一道调的是“电压”——接收端判断 0 和 1 的判决门限。门限偏了，眼图在垂直方向上就被切掉一块。

做法和时序训练一样：遍历设定值，找左右边界，取中间。而且它必须配合 Write DQ Training 一起做——因为只有通过连续的读写操作，才能验证某个 VrefQ 值是否真的让误码率降下来。

四、四道体检的顺序和代价

把四道串起来，大致是这么一条链：

这个顺序有内在逻辑：阻抗是地基，占空比是时钟，相位是采样，电压是门限。 地基不稳，后面调什么都是浮的。

代价也很实在：

  • 训练期间总线被占用，不能传数据。一次完整的训练要花的时间，是上电那几百毫秒里不可忽略的一块；
  • 温度大幅变化后可能要重训。芯片热了，延迟和阻抗都变了，之前标定的值可能失效；
  • 短校准可以周期性插入，但太频繁会明显拉低带宽——所以实践中通常在正常运行时不做定时 ZQ 短校准，只在必要节点做。

这就是工程上的典型权衡：余量要靠训练换，带宽也要靠训练换，两者互相抢。

总结：四道体检，四个维度

  • ZQ：治阻抗不匹配。用外部精密电阻当标尺，温度变了就再校。校准期间总线不能动、DQ 要高阻。
  • DCC：治占空比偏差。让时钟自己跑起来量自己，返回的数据不用管。
  • Read DQ / Write DQ：治相位偏移。读调接收端延迟，写调发送端延迟，靠“写进去再读回来”验证。
  • VrefQ（LPDDR4）：治判决门限偏差。和时序训练一样，扫边界取中点。

四道的共同思路只有一句话：先找到能用的边界，再退到中间去。

收尾：两端对上眼之后，还剩一笔算术

四道体检做完，主控和颗粒终于能在高速下听懂对方。但“能跑”不等于“跑得快”。

接口跑通之后，下一个问题马上跟上来：这颗颗粒到底能给到多少带宽？

规格书上写着 4.8 Gb/s、8 条 DQ 并行、16 个通道——数字乘一乘，看着能把 PCIe 塞满。可实际往颗粒里写，往往是另一个数量级。差在哪儿？
